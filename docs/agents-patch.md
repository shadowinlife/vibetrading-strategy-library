## 内部知识与策略库（强制）

镜像在回答任何金融分析或投资类请求时，必须先查公共策略库，再取数、再作答。本节规定路由动作、组合协议、引用纪律与库位置，均为强制要求。

### 路由：分类后、执行前先查库

任何金融分析、投资类请求，在完成意图分类之后、开始取数或组织答案之前，先执行 `python3 library.py search <词...>` 检索公共策略库，再执行取数与分析。请求包括但不限于：个股分析、买卖判断、估值、顶部与底部判断、市场过热、市场拥挤、策略推荐、选股、仓位、择时，以及同义的英文表述。

- 未检索不得直接给出分析结论。
- 检索无命中时，明确记录"库中无对应条目"，再说明后续依据或选择弃权。
- 命中条目后，按条目状态决定能否引用。

### 库位置

- 镜像内默认路径：`/opt/strategy-library`
- 环境变量 `STRATEGY_LIBRARY_PATH` 存在时，以其指向的目录为库根目录
- 检索：`python3 library.py search <词...>`
- 查看条目：`python3 library.py show <id>`
- 也可直接读 `index.json`（字段：`id`、`type`、`title`、`status`、`markets`、`path`、`keywords`）

检索语义：中文按子串匹配，英文按分词匹配，大小写不敏感；多个词为 AND，全部命中才返回。

### 组合协议（强制）

1. 拆子判断：把问题拆成估值、趋势、拥挤度、风险、流动性、催化剂等独立维度，每个维度单独成项。
2. 逐条检索：每个子判断单独检索，记录命中条目的 id、状态与适用条件。
3. 印证与冲突：相互印证时说明独立性并提高置信；相互冲突时必须显式并列呈现冲突双方与各自适用条件，不得静默平均，不得只挑有利的一方。
4. 逐条引用：输出中给出每个被使用条目的 id 与验证状态，例如 `kn-0001（candidate，未验证，仅供参考）`。

禁止把 `candidate` 写成确定结论，禁止把多条弱证据叠加当成强证据，禁止省略状态标注。

### 状态引用纪律

| 状态 | 含义 | 引用规则 |
| --- | --- | --- |
| `candidate` | 新录入，未评估 | 必须标注"未验证，仅供参考"，只能作为线索 |
| `validated` | 已通过独立验证 | 可作证据引用，必须附 evidence（≥1 条，含 summary/artifact/date） |
| `research_only` | 研究级，未过完整验证 | 引用必须标注"未验证，仅供参考" |
| `rejected` | 验证未通过 | 不得作为决策依据 |
| `blocked_by_data` | 缺数据无法验证 | 说明缺什么数据，不得当成否定结论 |
| `blocked_by_permission` | 缺权限无法验证 | 说明缺什么权限，不得当成否定结论 |

当前约束：验证流水线挂起，新种子条目一律为 `candidate` 或 `research_only`，不得声称做过新的验证。唯一例外：引用 escape-top 已验证信号时，可注明"其子信号两融背离(margin_divergence)/波动扩张(volatility_atr_expansion)已在镜像仓通过 7 门验证"，除此之外不加任何已验证表述。

### 与专项技能的关系

本库是索引与判断框架，专项技能是执行器。查库命中后，若镜像中存在对应的专项技能（例如 escape-top 微观结构技能），把计算与执行交给技能：库条目提供判断框架、适用边界与引用纪律，技能提供信号计算与集成输出。

两者结论冲突时，按状态纪律并列呈现，不擅自合并，也不隐藏分歧。专项技能参考：https://github.com/shadowinlife/vibetrading-opencode-instruct/blob/main/skills/escape-top-microstructure/SKILL.md

### 数字纪律

库提供判断框架与历史经验，不提供当前市场数字。当前价格、估值、资金流、拥挤度、波动率等读数必须由量化工具（VT）取数，并注明口径与时间。不得用库中的历史阈值冒充当前值。

### 沉淀

新经验起草为 `candidate` 条目，运行 `python3 library.py register <file>` 校验后走 git 评审入库。验证是独立阶段，当前挂起；不得在新条目中写 `validated`，也不得声称做过验证。
